QEMU boot image (Image.ipados)
==============================

Built by: tools/make_boot_image.py from the published qemu/Image.
Host check: python3 tests/test-boot-image.py

What this image is
------------------
A patched copy of qemu/Image for local QEMU virt. It is not a flashable
tablet firmware image. SpringBoard is not claimed.

Patches applied
---------------
1. trust_cache_runtime_init Image4/AMFI NULL panic bypassed (instruction
   patches only; the intentional segment slide 0x175b0 is left alone).
2. IOStartIOKit call in bsd_init replaced with `mov w0, #0`.
3. vfs_mountroot NULL mount slot redirected to slid lapis_mount.
4. rd=md0 kept; AMFI/debug args added; stock slto_us/tlto_us (1–2s) raised
   to 3600s so QEMU TCG does not panic on ticket/spin lock timeouts.
5. Mount trampoline kicks LapisBlk/UFS (stock starts them after
   mountroot), then lapis_mount waits forever for LapisBlk ROOT=1
   (status at 0xfffffe0007daf000) instead of racing to md0. The wait
   loop delays 10ms per poll so those threads can run on CPU0.
6. VM pageout-scan enter: first CPU only claims the count; the store that
   publishes wait-lock 0xfffffe0007d604fc is NOPed so waiters do not spin at
   0xfffffe0007576a58 while the owner runs the scan body (avoids a tickets
   spinlock AB-BA with the scan wait).
7. Ticket-lock timeout stubs (RT 0xfffffe0007ba0590..620) return instead of
   panicking; QEMU TCG still trips them and callers retry the acquire.
8. NULL vtable guard for RT 0xfffffe0007b49968 / 0xfffffe0007b499d0
   (ldr [x8,#0x1c0] with x8==0 caused FAR 0x1c0 panic after mount).
9. NULL ops guard for RT 0xfffffe000793a084 (ldr [x9,#0x1a0] FAR 0x1a0).
10. Stock `b .` at runtime 0xfffffe0007afdd90 (processor state 2 /
    PROCESSOR_OFFLINE_RUNNING) redirected to the normal state-dispatch
    path at 0xfffffe0007afdd9c.
11. CS/AMFI boot-arg ADD immediates corrected (stock points mid-cstring);
    CSM gate skipped; cs_enforcement __DATA default forced to 0; invalid-page
    CS kill softened. Stock left cs_enforcement=1 so init died under CS.

Verified in QEMU (this tree)
----------------------------
- Requires ~43G guest RAM:
    -M virt,...,memory-backend=ram0 -m 43G \
    -object memory-backend-ram,id=ram0,size=43G,reserve=off,prealloc=off
  With -m 8G the early stub stops in the exception dump WFE at 0x40201910.
- Kernel past Image4 panic; lapisfs mounts md0; NULL vtable FAR sites guarded.
- load_init_program at RT 0xfffffe00078d7b18 is hit; cs_enforcement reads 0.
- Msgbuf shows pid 1 is launchd, then (pre-wait-forever patch, md0 root):
    initproc failed to start -- ... Library not loaded: /usr/lib/libSystem.B.dylib
    Reason: tried: '/usr/lib/libSystem.B.dylib' (no such file, no dyld cache)
  md0 (~1.98 MiB) has launchd/dyld but no shared cache; fullroot.img does.
- With LapisBlk/UFS kick + wait-forever + 10ms yield, lapis_mount takes
  LapisBlk ROOT and mounts fullroot:
    MOUNTED size=135958000 entries=11b disk=1 (5193957376 bytes, 283 entries).
  On fullroot, dyld opens dyld_shared_cache_arm64e, preads the header, and
  calls F_ADDFILESIGS_RETURN. ubc_cs_blob_add reached _accelerate_entitlement_queries
  (RT 0xfffffe000793a064); with IOKit skipped the ops object is NULL. The
  null-ops guard at 0xfffffe000793a084 used to return into the epilogue with
  the blob pointer still in w0, which ubc_cs_blob_add treated as EPERM → dyld
  "code signature registration for shared cache failed". The guard now returns
  w0=0. The non-platform-binary EPERM gate at 0xfffffe0007938ff0 is also
  softened.
- With those fixes, GDB on fullroot shows: UBC_CS_BLOB_ADD_RET w0=0, many
  subcache lookups/mmaps, SR_MAP2, then MAP_WITH_LINKING. Msgbuf no longer
  says "no dyld cache" / libSystem missing.
- Shared-cache auth slide convert clears OS_REASON_SIGNAL 0xb (raw chain FAR).
- Dyld pager Auth64 nopac accepts pointer_format 12 (USERLAND24); msgbuf no
  longer prints `unknown pointer_format 12` / SIGBUS 0xa. Launchd now dies in
  `_container_init(): sandbox_get_container_expected() failed: -1`
  (namespace 18 subcode 0x2).

Not verified
------------
- launchd past sandbox container init after dyld page-in linking.
- DSMOS / SpringBoard / UI.
- Tablet / TB520FU hardware.

QEMU command
------------
  qemu-system-aarch64 -nodefaults -display none \
    -M virt,virtualization=off,secure=off,gic-version=3,memory-backend=ram0 \
    -m 43G -object memory-backend-ram,id=ram0,size=43G,reserve=off,prealloc=off \
    -cpu max -smp 8 \
    -drive if=none,id=ufsdisk,file=/path/to/fullroot.img,format=raw,readonly=on \
    -device ufs,id=ufs0 -device ufs-lu,drive=ufsdisk,lun=0 \
    -kernel qemu/Image.ipados -no-reboot

fullroot.img is the 5 GiB LAPISFS GPT image; do not commit it.

SHA-256 of Image.ipados is printed by tools/make_boot_image.py.
