## before (after skip-chained alone)
- MOUNTED → MWL → OS_REASON ns=2 code=0xb
- First userspace data abort: write translation fault (esr …047) at
  FAR = slid `__dyld_apis` (unslid 0x1ec090040 in `.33.dylddata` map[3],
  mappingWithSlide flags 0x44 = CONST|TPRO), PC dyld VA 0x4f2fc
  `str x20,[x0]`.
- msgbuf: `vm_shared_region_start_address() returned 0x1` (unchanged vs #15).

## rejected alternatives
- Clear TPRO/AUTH/CONST flags on `.33/.70/.81` mappingWithSlide → map[3]
  still unmapped; same FAR class.
- Relocate Mach-O `__dyld_apis`/`__helper` section addrs into map[4] →
  map[4] also has no VME at dyld install time (pthread code patch alone
  had masked this; the DATA seed was never required for the BRK bypass).
- Expand map[2] over map[3] → regresses to ns=6/0x1 "no dyld cache".
- Local-store + skip helper only to 0x4f38c → FAR=0 at field copies that
  expect helper-filled pointers at x20+0x98.

## patch
tools/patch_fullroot_dyld_tpro_local.py on /usr/lib/dyld:

1. Cave VA 0x19e4: `adrp/add/str/ret` → `__DATA.__common` 0xb4300
2. Store VA 0x4f2fc: `str x20,[x0]` → `bl 0x19e4`
3. Helper VA 0x4f32c: `mov x24,x0` → `b 0x4f3c8` (skip PAC install +
   NULL field copies)

Unit: tests/test-patch-fullroot-dyld-tpro-local.py

## after

  gdb-shared-region-tpro.txt).
- OS_REASON still ns=2 code=0xb (SIGSEGV) — same signal class, new site.
